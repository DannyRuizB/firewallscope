# A hand-written iptables-restore file, edited once too often: two rules match
# on an interface the chain never sees. iptables refuses BOTH lines - "Can't
# use --out-interface with INPUT", "Can't use --in-interface with OUTPUT"
# (measured, iptables 1.8.11) - and iptables-restore stops there and loads
# NOTHING, so the boot that replays this file ends with no firewall at all.
*filter
:INPUT DROP [0:0]
:FORWARD DROP [0:0]
:OUTPUT ACCEPT [0:0]
-A INPUT -i lo -j ACCEPT
-A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
-A INPUT -m conntrack --ctstate INVALID -j DROP
# "only accept ssh on the uplink" - written with -o by muscle memory
-A INPUT -o eth0 -p tcp --dport 22 -j ACCEPT
# the legitimate shape of the same idea, for contrast
-A INPUT -i eth0 -p tcp --dport 443 -j ACCEPT
-A FORWARD -i eth1 -o eth0 -j ACCEPT
# "log what comes back in on the uplink" - in the chain that only sees what leaves
-A OUTPUT -i eth0 -j LOG --log-prefix "OUT-UPLINK: " --log-level 4
COMMIT
