# A hand-written /etc/iptables/rules.v4 with a default-deny OUTPUT. The web
# client line was "tightened" to ephemeral source ports by tacking --sport
# onto the multiport. After -m multiport, --sport is not the tcp match's
# option: getopt reads it as multiport's --sports, and one multiport match
# takes one port list. Measured on THIS file (iptables 1.8.11, nf_tables and
# legacy): iptables-restore stops at the web line ('multiport: option
# "--source-ports" cannot be used together with "--destination-ports"'),
# rc 2, *filter loads nothing and the DROP policies never apply - the box
# boots open. The DNS line below it, with -m udp loaded first, is fine.
*filter
:INPUT DROP [0:0]
:FORWARD DROP [0:0]
:OUTPUT DROP [0:0]
-A INPUT -i lo -j ACCEPT
-A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
-A INPUT -p tcp --dport 22 -j ACCEPT
-A OUTPUT -o lo -j ACCEPT
-A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
-A OUTPUT -p tcp -m multiport --dports 80,443 --sport 1024:65535 -j ACCEPT
-A OUTPUT -p udp -m udp --sport 1024:65535 -m multiport --dports 53,123 -j ACCEPT
COMMIT
